# 안랩 코딩테스트 직전 정리본

## 1. 문제 보고 알고리즘 고르기

| 이런 표현이 보이면    | 먼저 생각할 것              |
| ------------- | --------------------- |
| 중복 개수, 빠른 검색  | `dict`, `set`         |
| 모든 경우, 모든 순서  | 완전탐색, DFS             |
| 연결된 노드 전부 찾기  | DFS / BFS             |
| 동일 비용 최단거리    | BFS                   |
| 네트워크 몇 개인가    | DFS / BFS + `visited` |
| 앞에서 넣고 앞에서 꺼냄 | Queue, `deque`        |
| 최근 원소부터 처리    | Stack                 |
| 정렬 후 양끝 비교    | 투 포인터                 |
| 매 순간 최선 선택    | 그리디                   |
| 정렬된 데이터에서 탐색  | 이분탐색                  |
| N이 매우 작음      | 완전탐색 가능성 확인           |
| N이 100,000 수준 | O(N²) 피하기             |

## 2. Python 자료구조 핵심 문법

```python
# dict
d = {}
d[key] = d.get(key, 0) + 1

# set
s = set(arr)
if x in s:
    ...

# queue
from collections import deque

q = deque()
q.append(x)
x = q.popleft()
q[0]                    # peek

# stack
stack = []
stack.append(x)
x = stack.pop()
stack[-1]               # peek

# 정렬
arr.sort()                    # 원본 오름차순
arr.sort(reverse=True)        # 원본 내림차순
new_arr = sorted(arr)         # 새 리스트

# 정렬 기준 함수 제공
arr.sort(key=lambda x: x[1])

# 여러 조건
arr.sort(key=lambda x: (x[0], x[1]))

# 첫 번째 오름차순, 두 번째 내림차순
arr.sort(key=lambda x: (x[0], -x[1]))

# 슬라이싱
arr[a:b]                 # a부터 b-1
```

`key`에는 **각 원소에서 정렬 기준값을 반환하는 함수**를 넣는다.

```python
def get_key(x):
    return x[1]

arr.sort(key=get_key)
```

주의할 연산 복잡도:

```python
x in list       # O(N)
x in set        # 평균 O(1)
x in dict       # 평균 O(1)

min(list)       # O(N)
max(list)       # O(N)
sum(list)       # O(N)

arr[a:b]        # O(잘라낸 길이)
```

`cmp_to_key`

```python
from functools import cmp_to_key

def compare(a, b):
    if a < b:
        return -1    # a가 앞
    elif a > b:
        return 1     # b가 앞
    return 0         # 동일

arr.sort(key=cmp_to_key(compare))
```

기억할 건:

```text
compare(a, b)

음수(-1) → a가 앞
0        → 순서상 동등
양수(1)  → b가 앞
```

## 3. BFS 기본형

**최단거리 + 모든 이동 비용 동일 → BFS 우선**

```python
from collections import deque

q = deque([start])
visited[start] = True

while q:
    cur = q.popleft()

    for nxt in graph[cur]:
        if visited[nxt]:
            continue

        visited[nxt] = True
        q.append(nxt)
```

최단거리 기록:

```python
dist[nxt] = dist[cur] + 1
```

핵심은 **큐에 넣는 순간 `visited` 처리**.

## 4. DFS 기본형

**한 선택을 하고 끝까지 들어간 뒤 돌아오기**

```python
def dfs(cur):
    visited[cur] = True

    for nxt in graph[cur]:
        if not visited[nxt]:
            dfs(nxt)
```

완전탐색형:

```python
def dfs(state):
    if 종료조건:
        return

    for choice in choices:
        dfs(선택한_다음_상태)
```

피로도, 모음사전처럼 **선택 트리를 끝까지 탐색**할 때 사용.

## 5. 그래프 기본형

무방향 연결:

```python
graph = [[] for _ in range(n + 1)]

for a, b in edges:
    graph[a].append(b)
    graph[b].append(a)
```

연결 요소 개수:

```text
모든 노드 순회
→ 아직 방문 안 했다
→ 네트워크 +1
→ DFS/BFS로 연결된 노드 전부 방문
```

## 6. 완전탐색 판단

입력 크기를 먼저 본다.

```text
N ≤ 8
→ N!도 고려 가능

N ≤ 20
→ 2^N 고려 가능

N ≈ 100
→ O(N²) 대체로 가능

N ≈ 100,000
→ O(N²) 위험
→ O(N), O(N log N) 목표
```

`2^N`개 선택:

```python
for i in range(2 ** n):
    ...
```

순서를 전부 시도해야 한다면 DFS, 순열 등을 생각한다.

## 7. 투 포인터 + 그리디

정렬된 배열의 양쪽을 사용할 때:

```python
arr.sort()

left = 0
right = len(arr) - 1

while left <= right:
    ...
```

구명보트 핵심:

```text
가장 무거운 사람 + 가장 가벼운 사람 가능
→ 둘이 보냄

불가능
→ 가장 무거운 사람은 누구와도 못 탐
→ 혼자 보냄
```

**무게를 꽉 채우는 것과 보트 수를 최소화하는 것은 다른 목표**라는 점 주의.

## 8. Stack 패턴

주식가격처럼:

> 지금 들어온 값 때문에 이전 값의 결과가 확정되는가?

이면 Stack 고려.

```python
stack = []
answer = [0] * len(arr)

for i in range(len(arr)):
    while stack and 조건:
        prev = stack.pop()
        answer[prev] = i - prev

    stack.append(i)
```

```text
Queue → 먼저 들어온 것부터
Stack → 최근에 들어온 것부터
```

## 9. 정렬과 특수 정렬

### 기본 정렬

```python
arr.sort()
arr.sort(reverse=True)
```

### 특정 값을 기준으로 정렬

```python
arr.sort(key=lambda x: x[1])
```

예:

```python
arr = [
    ["A", 30],
    ["B", 10],
    ["C", 20]
]

arr.sort(key=lambda x: x[1])

# B 10
# C 20
# A 30
```

### 여러 기준

```python
# 1번 값 오름차순, 같으면 2번 값 오름차순
arr.sort(key=lambda x: (x[0], x[1]))

# 1번 값 오름차순, 같으면 2번 값 내림차순
arr.sort(key=lambda x: (x[0], -x[1]))
```

### 두 원소를 직접 비교해야 할 때

`가장 큰 수`처럼 `a+b`와 `b+a`를 직접 비교해야 한다면 `cmp_to_key`.

```python
from functools import cmp_to_key

def compare(a, b):
    if a + b > b + a:
        return -1
    elif a + b < b + a:
        return 1
    return 0

arr.sort(key=cmp_to_key(compare))
```

반환값:

```text
음수 → a가 b보다 앞
0   → 동일
양수 → b가 a보다 앞
```

정리:

```text
단순 오름/내림
→ sort()

원소 하나에서 정렬 기준을 뽑을 수 있음
→ key / lambda

a와 b를 직접 비교해야 순서를 결정할 수 있음
→ cmp_to_key
```

## 10. 가중치 최단거리

```text
모든 간선 비용 동일
→ BFS

비용이 0 또는 1
→ 0-1 BFS

서로 다른 비용, 모두 0 이상
→ 다익스트라

음수 가중치 존재
→ 벨만-포드

모든 정점 사이의 최단거리
→ 플로이드-워셜
```

특히 **양수 가중치 최단거리 → 다익스트라 + `heapq`** 정도는 기억.

## 11. 이번 연습에서 특히 주의할 것

```text
1. continue 아래 증감문이 실행되지 않는 버그 주의

2. BFS는 enqueue할 때 visited 처리

3. 대응되는 데이터 여러 개는 tuple로 함께 관리하는 것도 고려

4. 재귀 DFS는 Python 재귀 깊이 주의

5. list slicing은 공짜가 아님

6. min(), max(), sum()도 O(N)

7. 문제 제한조건부터 확인
   N이 작다면 완전탐색이 정답일 수 있음

8. sum, list, dict 같은 Python 내장 이름을
   변수명으로 덮어쓰지 않기

9. 정렬 문제에서는
   sort → key → cmp_to_key 순으로 생각

10. 결과가 나중에 확정되는 문제는
    answer를 append하기보다 인덱스로 기록할 수 있는지 확인
```

## 시험장에서 막히면

**입력 크기 확인 → 자료구조 결정 → 완전탐색 가능한지 확인 → 정렬이면 `sort/key/cmp_to_key` 판단 → 그래프면 DFS/BFS → 최단거리면 가중치 확인 → 정렬 후 양끝이면 투 포인터 → 현재 값이 이전 값의 결과를 확정하면 Stack**

이 흐름만 빠르게 훑어도 알고리즘 후보를 상당히 좁힐 수 있어.
